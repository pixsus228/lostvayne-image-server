# LOSTVAYNE-LOQ — Сервер зображень 2.0

Модульний високопродуктивний сервіс для зберігання, валідації, фільтрації та аналітики зображень, розгорнутий у Docker-середовищі з балансуванням через Nginx.

## 🏗️ Архітектура проекту
Проект спроектовано за принципом розділення відповідальності (**Single Responsibility / SRP**):
- `backend/app.py` — чистий HTTP-диспетчер (роутер запитів).
- `backend/handlers.py` — ізольована бізнес-логіка обробки та робота з диском.
- `backend/database.py` — репозиторій для атомарної взаємодії з PostgreSQL через пули транзакцій `psycopg`.
- `backend/utils/validators.py` — перевірка розміру (макс. 5 МБ) та дозволених типів файлів.

## 🚀 Специфікація REST API

### 1. Завантаження та перегляд зображень
- `POST /api/upload` — завантаження нового зображення. Перед збереженням автоматично вираховується контрольна сума SHA-256. Якщо знайдено дублікат, файл не дублюється на диску, а повертається наявний запис.
- `GET /api/images/{filename}` — отримання метаданих зображення. Кожен виклик автоматично інкрементує лічильник переглядів (`views = views + 1`).
- `GET /api/images/popular` — отримання списку найпопулярніших зображень за кількістю переглядів. Параметри: `?limit=10`.

### 2. Пошук, фільтрація та пагінація
- `GET /api/images` — динамічний пошук за фільтрами. Приймає query-параметри:
  - `search` — пошук за оригінальною назвою (ILIKE %s).
  - `file_type` — фільтрація за розширенням файлу (наприклад, `.png`).
  - `date_from` / `date_to` — вибірка за часовим проміжком.
  - `page` / `limit` — постранична навігація (пагінація).
- `GET /api/images/count` — загальна кількість знайдених зображень за поточною групою фільтрів (використовується фронтендом для розрахунку сторінок).

### 3. Статистика та аналітика
- `GET /api/stats` — загальна аналітика сервера: підрахунок кількості файлів та сумарного об'єму на диску з групуванням за типами розширень (`GROUP BY file_type`).
- `GET /api/images/{filename}/stats` — детальна індивідуальна статистика конкретного зображення (дата завантаження, розмір, кількість переглядів).

### 4. Кошик (Soft Delete) та відновлення
- `DELETE /api/images/{filename}` — м'яке видалення. Зображення приховується з загального списку (`deleted_at = NOW()`), але фізично залишається в системі.
- `GET /api/trash` — перегляд списку видалених зображень, що знаходяться в кошику (підтримує параметри `page` та `limit`).
- `POST /api/images/{filename}/restore` — відновлення зображення з кошика в загальний доступ (`deleted_at = NULL`).
- `DELETE /api/trash` — остаточне зачищення кошика. Видаляє записи з бази даних та фізично стирає відповідні файли з дискового простору сервера (`uploads/`).
